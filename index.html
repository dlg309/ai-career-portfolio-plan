ENGINEERING / DELIVERY PLAN

Keep the research maintainable.

Use the existing static HTML, CSS, JavaScript modules, and build script. Add a dependency only when a measured need justifies it.

Architecture and quality

research-data.mjs holds sourced records; logic.mjs handles pure filtering, comparison, and storage rules; app.mjs renders the UI; HTML and CSS define semantic structure and layout. Keep each module responsible for one concern (SOLID's single-responsibility principle) and extend data records without changing filter behavior when possible. Escape rendered text, keep source links and check dates beside claims, and review small diffs.

Run Node tests for data integrity and behavior, npm run build for static output, and a focused browser check for keyboard navigation, visible focus, narrow-screen overflow, and the localStorage tracker. Add linting or broader automation only for a recurring defect; preserve the skip link, headings, labels, and table headers.

AI-assisted workflow

Research → compare → plan → approve → implement → test → review. Give the AI only the relevant posting excerpts, project evidence, and files for each task. Ask it to flag unsupported claims and uncertain dates, then verify against original sources. Reuse structured records and focused checks to save tokens. Diego decides career priorities, private eligibility, and what claims are publishable.

Definition of done: a change has a source or project artifact, stated uncertainty, working navigation, passing relevant tests and build, and a human review of the public claim.
