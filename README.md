## Portfolio project record

**Reader hypothesis:** Primary, an internship reviewer scanning for Diego's contribution, code, checks, and résumé. Secondary, a potential collaborator looking for a practical problem-solving example. These are assumptions for design, not a recruiter study.

**Promise:** For an internship reviewer, the portfolio makes it easy to see what I built, how I checked it, and where to inspect the work next.

**Voice and character:** Clear, curious, practical; a builder who explains decisions. The [existing portfolio record](https://github.com/dlg309/Diego-Guevara-Portfolio/blob/main/docs/PORTFOLIO_RECORD.md) selects an evidence-first direction. This research site keeps that choice visible and compares it with a more editorial approach. The [Career & Portfolio Lab](https://jasdeepn24.github.io/is218-career-portfolio-research/) informed scannable research sections; [AI Career Atlas](https://keithwilliams.org/ai-career-research/) informed clear source and next-step cues. No content or visual assets were copied.

**Design alternatives:** A uses a restrained grid, high contrast, and evidence links beside claims. B uses an editorial layout with a larger game feature and expressive display type. A is selected because the reader needs to locate contribution and verification quickly; B adds character but moves proof farther down. Both use the same introduction, projects, and action. The live portfolio has A; this site documents the decision rather than presenting a second finished portfolio.

**Portfolio stories and acceptance checks:**

1. As an internship reviewer, I want to identify Diego's contribution so I can assess it fairly. Check: each case study distinguishes his work, collaborators' work, and limits.
2. As a technical reviewer, I want to inspect a project so I can verify claims. Check: the project repository and relevant specification, change, or test evidence open from its case.
3. As a collaborator, I want to understand the problem and outcome so I can decide whether to contact Diego. Check: each case gives a concise problem, decision, checked result, and honest limit.
4. As a visitor on a phone or keyboard, I want to navigate the material. Check: no horizontal overflow at narrow widths, visible focus states, and working section links.

**Evidence to carry forward:** [RPS repository](https://github.com/dlg309/RPS_Game218), [RPS specification](https://github.com/dlg309/RPS_Game218/blob/main/SPEC.md), [ALPFA collaborative app](https://github.com/AnabhayanA/alpfa-njit-app), and [Tempo AI Assistant](https://github.com/dlg309/Tempo-AI-Assistant). The [existing portfolio record](https://github.com/dlg309/Diego-Guevara-Portfolio/blob/main/docs/PORTFOLIO_RECORD.md) documents contribution and current limitations. The required course group customer case study remains unconfirmed there; ALPFA is collaborative work but is not claimed as that course project.
